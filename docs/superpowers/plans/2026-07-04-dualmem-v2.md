# dualmem v2 — Three-Primitive Rewrite

**Date:** 2026-07-04
**Status:** Draft
**Supersedes:** Phases 2–3 of `2026-07-04-memory-simplification.md` (Phase 1, SWR + incremental codemap refresh, shipped in `ceda26e` and carries forward unchanged)
**Reference:** design principles doc in Obsidian vault — `Claude Notes/Planning/Agent Memory Design Principles (geoffrey rewrite).md`

## Motivation

The current system (~35k LOC in `dualmem/`, ~15 ranking-adjacent subsystems) tries to fix noisy writes with clever reads. v2 inverts that: store less, store better, supersede explicitly, and make retrieval mostly agent-pulled rather than assembly-pushed. Instead of instrumenting old layers for weeks to justify pruning (old Phase 2), v2 decides by design and instruments *itself* from day one.

## Core principles (see vault doc for full argument)

1. Anything re-derivable from the repo is a cache, never authoritative. Git history is free institutional memory (co-change, hotspots, decision log).
2. A wrong/stale memory is worse than none → **every item carries provenance** (commit, date, source) and staleness is surfaced, not hidden.
3. Pull > push: tiny pinned block at session start; precise query tools at decision points.
4. Write-time quality beats read-time ranking: a curated store of ~200 facts needs recency + file-match, not a learned reranker.
5. Human-readable store: the user must be able to see and correct what the system believes.
6. Inferred understanding (from scanning/docs) decays; verified understanding (earned by doing, esp. dead ends) accumulates.

## The three primitives

### P1 — Derived index (rebuildable, never authoritative)

- **Codemap** as shipped in Phase 1: stale-while-revalidate, incremental git-diff refresh, `Stale`/`CommitsBehind` markers. HDC code search stays (cheap, no API calls).
- **Co-change graph: git-derived only.** `git_cochange.go` survives; memory-based `cochange.go` is deleted (old plan already flagged the merge; v2 resolves it in git's favor).
- Invariant (unchanged): `AssembleContext` never triggers a filesystem walk.

### P2 — Durable facts (the actual memory)

New `facts` table replacing detail memories as the primary write target:

```sql
CREATE TABLE facts (
  id            TEXT PRIMARY KEY,
  namespace     TEXT NOT NULL,        -- repo scope; '' = user-global (preferences)
  kind          TEXT NOT NULL,        -- decision | deadend | gotcha | preference | reference
  text          TEXT NOT NULL,        -- one to three sentences, self-contained
  files         TEXT,                 -- JSON array of repo-relative paths
  source        TEXT NOT NULL,        -- verified | inferred | doc | migrated
  git_commit    TEXT,                 -- HEAD when written
  session_id    TEXT,
  created_at    INTEGER NOT NULL,
  superseded_by TEXT REFERENCES facts(id),
  embedding     BLOB,                 -- for recall(); the ONLY vector in v2
  hits          INTEGER DEFAULT 0,    -- passive usefulness counter
  last_hit_at   INTEGER
);
```

- **Kinds are the taxonomy, not layers.** `deadend` is first-class — highest-value, least-recorded memory type.
- **Supersede, don't decay.** Generalized-supersede work (`2026-04-09-generalized-supersede.md`) becomes the only lifecycle mechanism for facts. No importance decay, no salience curves.
- **Preferences are user-global** (`namespace=''`), gotchas/decisions are repo-scoped. Fixes the "re-learn Donny's preferences per repo" problem.
- **Human-readable mirror:** `dualmem facts export` writes grouped markdown (and `import` round-trips edits). SQLite stays source of truth; the mirror is for audit/correction. (Open question: write-through file instead?)

### P3 — Ephemeral session state

- Checkpoints/handoffs keep their current machinery, gain a TTL (default 7 days) and a sweep on session start.
- Distill's output target changes: instead of writing sketch episodes, distill proposes **fact candidates** (kind-classified) that get deduped against existing facts via supersede-check before insert.

## Assembly v2: pinned block + pull tools

**Pinned block** (hard cap ~500 tokens, assembled in <1s, no LLM calls):
1. Latest unexpired handoff (what was in flight)
2. User-global preferences (usually <10 facts)
3. Top-k facts whose `files` intersect paths changed since last session (git diff, already computed for codemap refresh)
4. One-line codemap status: `codemap: a013167, 4 commits behind — refreshing`

**Pull tools** (MCP surface — v2 explicitly may change tools, unlike old plan):
- `recall(query, kind?)` — embedding + file-match search over facts
- `precedent(approach)` — sugar for `recall(kind=decision|deadend)`; "did we already try/reject this?"
- `file_context(path)` — facts citing path + file annotations + git co-change neighbors
- codemap zoom tools — unchanged
- **Removed:** `rate_context` (dead feedback loop)

## Instrumentation from day one (task #5)

- Log served fact IDs per session (both pinned and pulled).
- **File-touch signal:** fact cites a file the session later read/edited → `hits++`. Source: distill transcript path first; hook logs if available (open question from old plan carries over).
- Stretch counters: **rediscovery** (agent greps for something an existing fact contained = retrieval miss) and **contradiction** (fact's claim conflicts with code at HEAD = staleness). Even approximate versions beat judge scores.
- `dualmem facts stats` — hits, dead facts (served N times, never hit), staleness candidates.

## Migration: curate once, keep the good memories

One-time `dualmem migrate-v2`:
1. **Safety net first:** full JSON dump of every table to `~/.dualmem-v1-archive/<namespace>.json`. Nothing is destroyed until this exists.
2. **Curation pass (LLM):** classify each existing detail memory / knowledge doc → fact kind, rewrite to self-contained text, stamp `source=migrated` + original timestamps. Narrative/episodic content → archive only.
3. **Supersede-dedup** within the migrated set (many near-duplicates expected).
4. **Human review:** emit the markdown mirror; user prunes/edits before `--commit` finalizes. This *is* the "prune based on my usage patterns" cleanup, done at migration time.

## Kill list (delete after migration, no instrumentation period)

| Component | Fate |
|---|---|
| Sketch arcs + profile (128d/64d projections) | Delete. Episodes archived in the v1 dump; distill retargets to facts. |
| Entity graph + structural boost | Delete. |
| Learned reranker (`reranker.go`) | Delete (trained on ratings that never arrive). |
| Curiosity signals, workflow hints | Delete. |
| `cochange.go` (memory-based) | Delete; git co-change wins. |
| Autopilot / anticipatory worker | Feature-flag off in v2.0; delete in v2.1 unless anticipation hit rate is demonstrated. |
| Importance scorer | Survives only as a write-time gate on fact candidates, not a read-time ranker. |

**Keep:** SQLite store, codemap + SWR/incremental refresh, checkpoints, file annotations, HDC code search, distill (retargeted), supersede machinery.

Target: `dualmem/` from ~35k LOC to a documented core, with `docs/architecture.md` giving every surviving box a one-line "why it exists".

## Cold start / onboarding (new repos, e.g. LearnCard)

`dualmem onboard` (builds on `2026-04-03-codebase-onboard-design.md`):
1. Build P1: codemap + git co-change from history (a repo new to the agent isn't new — git log has years of memory).
2. Ingest AGENTS.md / architecture / README as facts with `source=doc` — dated claims, not truth; code outranks docs on conflict.
3. Generate a "how do I run/test/deploy" runbook as `source=inferred` facts.
4. Inferred/doc facts are candidates for contradiction-checking and get superseded by verified facts as task work accretes.

## Non-goals

- No storage backend change (SQLite stays).
- No new ranking layers, ever, without a scorecard justification.
- No re-architecture of codemap (Phase 1 of the old plan stands as-is).

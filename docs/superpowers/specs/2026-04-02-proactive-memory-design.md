# Proactive Memory: File-Scoped Recall, Enhanced Wrap-Up, and Effort Markers

**Date:** 2026-04-02
**Status:** Draft

## Context

Claude sessions frequently spend significant effort rediscovering information from prior sessions — navigating to files, re-debugging known issues, or modifying code that has associated warnings. The dualmem system already stores memories, decisions, and warnings, but there are three gaps:

1. **No recall at point of use** — memories are loaded at session start based on the initial task query, but not surfaced when Claude opens a specific file mid-session. A warning about `rate_limiter.go` won't appear if the session task is "refactor error handling."
2. **Wrap-up saves too little** — the current wrap-up skill saves a single manual continuity note. The `distill` command can extract structured facts from the full session transcript but isn't wired into wrap-up.
3. **Effort-derived learnings evaporate** — when Claude spends many turns discovering something (root cause, file relationships), the learning isn't captured unless Claude explicitly saves it.

## Design

### 1. File-Scoped Recall via Read Hook

#### New CLI command: `dualmem file-context`

```bash
dualmem file-context <filepath> [--ns <namespace>] [--json]
```

Fast, no-LLM lookup that returns memories associated with a file. Implementation:

- Query `detail_memories` where `files` column contains the filename (basename match, not full path — memories store relative paths)
- Filter to high-signal types: `warning`, `decision`, `map` (skip `general`, `continuity`)
- Also search `knowledge_docs` whose `files` list contains the filename
- Return at most 5 results, sorted by salience descending
- Output format (plain text, one per line):
  ```
  [warning] Don't touch: rateLimiter cleanup() skips nil check intentionally (0.90, 2026-03-15)
  [decision] Chose SQLite over Postgres for zero-setup CLI (0.85, 2026-03-10)
  ```
- If no results: exit 0 with empty stdout (no output)

**File matching:** Basename match (e.g., `rate_limiter.go` matches `/Users/.../dualmem/rate_limiter.go`). If a basename appears in multiple directories, all matching memories are returned — this is acceptable since the memory text itself provides disambiguation context. A future optimization could match on relative path segments.

**Performance target:** <5ms. Pure SQLite, no embedding computation.

#### File index for zero-overhead hook filtering

To avoid running `file-context` on every Read (most files have no memories), maintain a lightweight index:

- **Location:** `/tmp/dualmem-file-index-<namespace-hash>.json`
- **Format:** `{"files": ["rate_limiter.go", "auth.go", "middleware.go"], "updated_at": "..."}`
- **Generated by:** `dualmem file-index [--ns <namespace>]` — new subcommand
- **Regenerated when:**
  - `dualmem context` runs (session start) — add file-index regeneration as a side effect
  - `dualmem add --files <...>` runs — if `--files` is provided, regenerate index after writing
  - `dualmem distill` runs — after writing facts with file associations
- **Query:** `SELECT DISTINCT files FROM detail_memories WHERE type IN ('warning','decision','map') AND namespace = ?` plus same from `knowledge_docs`
- Files are stored as basenames in the index (e.g., `rate_limiter.go` not `/Users/donny/Projects/.../rate_limiter.go`) since memories use relative paths

#### Claude Code Read hook

Add to `~/.claude/settings.json` under `hooks.PreToolUse`:

```json
{
  "matcher": "Read",
  "hooks": [
    {
      "type": "command",
      "command": "~/.claude/hooks/dualmem-file-recall.sh",
      "timeout": 5
    }
  ]
}
```

Hook script (`~/.claude/hooks/dualmem-file-recall.sh`):

```bash
#!/bin/bash
# Read hook: inject dualmem file-scoped memories before file reads
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
[ -z "$FILE_PATH" ] && exit 0

BASENAME=$(basename "$FILE_PATH")

# Check file index first (fast path — most files have no memories)
NS_HASH=$(echo "$INPUT" | jq -r '.cwd // empty' | md5sum | cut -c1-8)
INDEX="/tmp/dualmem-file-index-${NS_HASH}.json"

if [ -f "$INDEX" ]; then
  # Check if basename is in the index
  if ! jq -e --arg f "$BASENAME" '.files | index($f)' "$INDEX" >/dev/null 2>&1; then
    exit 0  # File not in index, skip
  fi
fi

# File is in index (or no index exists) — query for memories
RESULT=$(~/go/bin/dualmem file-context "$FILE_PATH" 2>/dev/null || true)
[ -z "$RESULT" ] && exit 0

echo "DUALMEM FILE CONTEXT for $BASENAME:"
echo "$RESULT"
```

**Behavior:** Hook stdout is injected as context into Claude's conversation. Claude sees the warnings/decisions before reading the file content.

### 2. Enhanced Wrap-Up

#### Update wrap-up skill

Replace the current manual `dualmem add --type continuity` approach with:

```bash
~/go/bin/dualmem distill --auto
```

The wrap-up skill (`~/.claude/commands/wrap-up.md` and project-level copy) should instruct Claude to:

1. Run `dualmem distill --auto` — extracts facts from the session transcript, writes them as memories, auto-triggers synthesis if >=3 facts written
2. If distill fails (e.g., no Gemini API key, empty session), fall back to manual `dualmem add --type continuity`
3. Optionally save any decisions/warnings Claude noticed but didn't save during the session

#### Persist session summary

Currently `distill` generates a `session_summary` in the LLM extraction but doesn't store it as a memory. Change:

- After extracting facts, also write the `session_summary` as a memory:
  ```go
  // In Distill(), after writing individual facts:
  if extraction.SessionSummary != "" {
      e.AddWithOptions(ctx, MemoryInput{
          UserMessage: extraction.SessionSummary,
          Type:        "continuity",
          Salience:    0.75,
          SessionID:   sessionID,
          Files:       collectAllFiles(extraction.Facts), // union of all fact files
      }, userID)
  }
  ```
- Type `continuity` with salience 0.75 (slightly above default, below warnings)
- Attach the union of all file paths from extracted facts so the summary is findable via file-context

### 3. Effort Markers via Skill Guidance

#### Skill updates

Add guidance to these skills (if they exist in the user's setup):

**systematic-debugging skill** — append:
> After resolving a bug that required >3 tool calls of investigation, save what you found:
> ```
> ~/go/bin/dualmem add --type warning --text "<root cause and why it was non-obvious>" --files "<affected files>" --salience 0.85
> ```

**brainstorming / writing-plans skills** — append:
> After exploring the codebase to understand a flow across multiple files, save the map:
> ```
> ~/go/bin/dualmem add --text "<flow description: A calls B which triggers C>" --files "<files in the flow>" --sector procedural
> ```

**General CLAUDE.md guidance** — add to the dualmem section:
> **Effort-based saving:** When you spend significant effort (>3 tool calls) discovering something non-obvious — a root cause, a file relationship, a constraint — save it immediately with `dualmem add`. Don't wait for wrap-up. The heuristic: "Would a fresh Claude starting this task be surprised by what I just learned?" If yes, save it.

These are soft conventions. The `distill` at wrap-up serves as a safety net to catch learnings that weren't explicitly saved.
